### Draw.io 線上繪圖工具操作實戰與流程設計

繪製流程圖時，除了紙筆手繪，也可以善用免費且免安裝的線上流程圖工具 Draw.io（diagrams.net）：
1. 建立畫布：開啟瀏覽器進入 https://app.diagrams.net/，選擇建立新圖表。
2. 拖曳標準圖形：從左側通用圖形庫中，將「橢圓（端點）」、「平行四邊形（資料）」、「長方形（處理）」、「菱形（判斷）」拖曳至畫布中。
3. 連接物件與箭頭：將滑鼠移至圖形邊緣的藍色十字箭頭，拖曳連接線至目標圖形，連接線會自動具備流向箭頭；雙擊連接線即可輸入文字（例如「Yes」或「No」）。
4. 匯出圖片：完成後點選「檔案 → 匯出為 → PNG/PDF」，即可取得高解析度流程圖圖片進行報告或課堂發表。
實戰情境：捷運悠遊卡進站閘門
① 輸入：乘客靠卡感應，系統讀取卡片餘額與票種。
② 判斷：卡片餘額是否 >= 20 元且卡片非黑名單？
③ 分支：
條件成立（Yes）：扣款並開啟閘門扇門通行。
條件不成立（No）：閘門螢幕顯示餘額不足，亮紅燈並發出警示音。
④ 輸出：閘門螢幕顯示卡片剩餘金額與通過指示。

### 破除國中生最常犯的三大演算法迷思

學習演算法時，同學們最常陷入以下三個迷思：
迷思 1：演算法就是很難、很高深的程式代碼？
正解：演算法是「思維與解決步驟的藍圖」，可以在紙筆上推導想通。寫程式只是最後將邏輯打字翻譯給電腦！
迷思 2：電腦很聰明，指令講個大概它就懂？
正解：電腦其實極度愚鈍但運算速度超快！它完全沒有常識，指令只要稍有模糊，電腦就會跑出荒謬的錯誤結果。
迷思 3：流程圖的框框只要我自己看得懂就好，符號隨便畫沒關係？
正解：流程圖是全球軟體與工程團隊共通的標準語言。若把處理長方形畫成決策菱形，會讓協同開發者產生嚴重誤判！

```text
讀取卡片餘額, 票種
IF 餘額 >= 20 AND 卡片狀態 == 正常 THEN
    閘門開啟
    扣除進站基本費用
    螢幕顯示 "請通過，餘額: " + 剩餘金額
ELSE
    發出嗶嗶警示聲
    亮起紅燈
    螢幕顯示 "餘額不足，請加值"
END IF
結束流程
```
