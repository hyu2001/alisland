探索導航：歡迎來到演算法思維探索島

演算法是現代資訊科技的基石。在日常生活中，我們無時無刻不在解決問題；而在電腦科學中，演算法更是將人類的模糊思維轉換為電腦精確執行的關鍵藍圖。本島嶼群由黃子宇 Zoe 老師規劃，帶領大家從生活步驟出發，逐步掌握演算法的五大黃金特性、CNS 流程圖四大符號、三大流程結構與 Draw.io 繪製實戰！

運算思維（Computational Thinking）四大核心

運算思維是所有人在數位時代必備的解決問題思維，包含四大能力： 1. 我是...問題拆解（Decomposition）：將複雜龐大的大問題，拆解成若干較小、易於處理的子問題（例如把買文具拆成進店、選物、結帳、離開）。 2. 模式識別（Pattern Recognition）：觀察不同問題之間的規律與相似之處（例如搜尋資料、泡麵、感應票卡的共通流程）。 3. 抽象化（Abstraction）：過濾掉無關緊要的次要細節，專注於解決問題的核心關鍵（例如流程圖簡化生活情境）。 4. 演算法設計（Algorithm Design）：為解決特定問題，設計出依序執行、有限且精確的具體步驟清單。

科技名人堂：伊隆·馬斯克（Elon Musk）的思維啟發

被譽為「科技狂人」的伊隆·馬斯克是 SpaceX、Tesla、SolarCity 的創辦人。他在推動可重複使用火箭與電動車革命時，極力推崇「第一原理思維（First Principles Thinking）」——把事物拆解到最基礎的物理事實與邏輯步驟，再由底層重新推演最佳路徑。這種抽絲剝繭、重視精確步驟與消除無效環節的思考模式，正是演算法思維在頂尖科技創新中的最佳典範。

1. 思維起點島

從生活經驗出發，認識演算法的本質，體會指令明確與步驟順序的關鍵重要性。

核心學習目標：能理解演算法是解決問題的明確步驟清單，並舉出生活中步驟不可逆的具體實例。

生活中的演算法：何謂演算法（Algorithm）？

廣義來說，演算法是一組在「有限步驟」內，用來解決特定問題或完成任務的「明確規則與指令清單」。演算法並非專屬於工程師的程式碼！做菜的食譜、組裝家具的說明書、數學直式除法的計算過程，本質上都是演算法。寫程式只是將演算法的邏輯「翻譯」給電腦理解，背後的邏輯流程才是核心所在。此外，步驟順序不可任意變動或顛倒！例如走進文具店購買文具的四步驟：『進入商店 → 挑選文具 → 結帳 → 離開商店』。若隨意省略「挑選文具」或「結帳」，就無法解決問題；若步驟顛倒變成「挑選文具後未結帳就離開商店」，更會構成違法犯罪行為！

指令明確性與模糊空間：消弭日常語言歧異

日常語言常帶有「模糊空間」，人類能靠常識猜測，但電腦極度愚鈍卻動作飛快，只要指令稍有模稜兩可，結果就會徹底失控！動腦挑戰：如果老師給全班一個指令說「請把紙對摺再對摺」，大家摺出來的會一樣嗎？學生 A 拿橫向長方形，先由左向右摺，再由上往下摺，摺出小長方形；學生 B 拿直向長方形，先由左向右摺，再沿對角線斜角摺，摺出奇怪的梯形；學生 C 拿橫向長方形，連續沿長邊對摺兩次，摺出細長紙條。由上方實例可知，模糊指令「對摺再對摺」因紙張方向未知、摺線未知而產出五花八門的結果。必須修正為精確指令：「將紙張橫向放置，沿長邊中線由下往上對摺一次，再沿短邊中線由左往右對摺一次」。起點固定、方向明確、步數固定，才能保證產出唯一正確結果！明確性是演算法的靈魂。

精確摺紙演算法指令

1. 將 A4 紙張長邊水平放置於桌面上。
2. 沿水平中線由下往上對摺一次，使上下長邊重合。
3. 沿垂直中線由左向右對摺一次，使左右短邊重合。
4. 壓平摺痕，產出規格為原尺寸 1/4 的對稱長方形。

自編練習題第 3 題：課堂摺紙活動中，老師說『對摺再對摺』卻讓三位同學摺出完全不同的形狀，主要原因為何？
  1. 因為紙張的材質不同造成變形
  2. 因為同學故意不聽老師的口令
  3. 因為日常語言具有模糊空間，指令未明確定義放置方向與摺線
  4. 因為對摺兩次的數學計算太過複雜

自編練習題第 4 題：下列哪一個指令敘述最符合電腦演算法『明確、無歧異』的要求？

  2. 「隨便拿一張紙摺一下」

2. 特性特檢島

深入演算法的五大黃金特性，並透過生活案例檢驗並修正不良 SOP。

核心學習目標：熟練演算法五大特性（輸入、輸出、明確性、有限性、有效性），並能為違反特性的步驟進行除錯。

演算法的五大黃金特性檢驗機

在資訊科技領域中，一套合格的演算法必須通過「五大黃金特性」的嚴格檢驗，缺一不可： 1. 輸入（Input）：可以有 0 個或多個輸入資料。例如計算圓面積需要輸入半徑（1個輸入）；而顯示固定字串則不需要任何外部輸入（0個輸入）。 2. 輸出（Output）：必須產生至少 1 個明確的輸出結果。如果一個演算法執行完畢沒有任何輸出或狀態改變，就失去了解決問題的意義。 3. 明確性（Definiteness）：演算法中的每一個步驟與指令都必須清晰明確，不可模稜兩可或存在主觀猜測的空間。 4. 有限性（Finiteness）：演算法必須在有限步驟與有限時間內執行結束，絕對不能陷入無窮迴圈（Infinite Loop）。 5. 有效性（Effectiveness，可行性）：演算法中的每個命令都必須是實際可行、能夠被執行的步驟；即使只用紙筆推演，也能在有限時間內一步步推算完畢以確定解決問題。

生活特檢室：不良泡麵 SOP 除錯診斷

請檢驗以下這份日常泡麵步驟，看看它是否符合演算法特性： 步驟 1：撕開泡麵碗蓋。 步驟 2：放入調味粉包。 步驟 3：倒水。 步驟 4：一直等待。 步驟 5：開動享用。 診斷與除錯： 步驟 3 違反明確性：『倒水』沒有說明倒冷水還是熱水？要倒多少水量？這會導致執行者困惑。應修正為：『注入沸騰熱水至碗內指示線』。 步驟 4 違反有限性（無窮迴圈）：『一直等待』沒有任何終止或跳出條件，電腦執行到這一步將會永遠卡死在等待狀態，永遠無法執行步驟 5！應修正為：『靜置等待 3 分鐘後結束等待』。

合格的泡麵演算法 SOP

1. 撕開泡麵碗蓋至標示折線處。
2. 取出調味粉包與油包，撕開倒入碗內。
3. 注入沸騰熱水（約 95-100°C）至碗內注水指示線。
4. 蓋上碗蓋，計時等待 3 分鐘。
5. 掀開碗蓋，以筷子攪拌均勻後開動享用（輸出：可享用的熱泡麵）。

自編練習題第 1 題：關於演算法五大黃金特性中的『輸入』與『輸出』，下列敘述何者正確？
  1. 輸入可以有 0 個或多個，但輸出必須至少有 1 個明確結果
  2. 輸入必須至少有 1 個，而輸出可以完全沒有
  3. 輸入與輸出都必須剛好有 1 個，不能多也不能少
  4. 演算法不需要任何輸出也能解決問題

正確答案：輸入可以有 0 個或多個，但輸出必須至少有 1 個明確結果
解析：演算法可以沒有外部輸入資料（0個輸入，例如印出內建招呼語），但必須至少產生 1 個具體的輸出結果，否則演算法毫無作用。

自編練習題第 2 題：在不良泡麵 SOP 中，步驟寫著『倒水』，這主要違反了演算法的哪一項特性？
  1. 有限性
  2. 有效性
  3. 明確性
  4. 輸出性

正確答案：明確性
解析：『倒水』未說明水溫（冷水或熱水）以及注水量，指令含糊模稜兩可，違反了明確性（Definiteness）。

自編練習題第 3 題：若演算法的步驟包含『一直等待』且沒有設定任何結束或跳出條件，會引發什麼問題？
  1. 運算速度變得非常快
  2. 違反有限性，電腦會陷入無窮迴圈而永遠無法結束
  3. 輸出結果會增加兩倍
  4. 會自動通過有效性檢驗

正確答案：違反有限性，電腦會陷入無窮迴圈而永遠無法結束
解析：演算法必須在有限步驟內結束。『一直等待』缺乏終止條件，會導致程式陷入無窮迴圈（Infinite Loop），違反有限性。

自編練習題第 4 題：演算法五大特性中的『有效性（Effectiveness，可行性）』代表什麼意義？
  1. 只要超級電腦跑得動，任何不可思議的步驟都可以
  2. 程式碼越短就越有效，不能超過五行
  3. 每個命令都必須是實際可執行的步驟，用紙筆也能完整推演完畢
  4. 所有的步驟都必須在 1 秒內瞬間完成

正確答案：每個命令都必須是實際可執行的步驟，用紙筆也能完整推演完畢
解析：有效性是指演算法中的每個步驟在現實中都是切實可行、能夠被執行的，即使僅用紙筆推演也能確認能解決問題。

3. 表達語言島

比較自然語言、流程圖與虛擬碼三大表達工具，學會依情境選擇最佳溝通媒介。

核心學習目標：能說出自然語言、流程圖與虛擬碼的優缺點與適用時機，並理解彼此轉換關係。

演算法的三種表達形式比較

當我們設計好解決問題的步驟後，需要將演算法「表達」出來，作為與他人溝通討論或後續撰寫程式的依據。演算法沒有限定唯一的表現方式，只要能清楚傳達邏輯即可。常見的三種表達形式為： 1. 自然語言（日常文字）：使用中文或英文等人類日常口語敘述步驟。優點是直覺親切，任何人都能看懂；缺點是篇幅冗長，且容易因文字多義性產生理解歧異。 2. 流程圖（Flowchart）：使用標準幾何圖形與箭頭流程線來呈現邏輯順序。優點是圖像化直觀、分支與循環清晰，是課本與工程界最推薦的表達工具！ 3. 虛擬碼（Pseudocode）：介於人類自然語言與真實程式語言（如 Python、C++）之間的結構化文字描述。它不拘泥於特定程式語言的繁瑣語法細節，但具備嚴謹的條件結構與縮排。

虛擬碼與程式語言的銜接

虛擬碼通常使用接近程式結構的關鍵字（如 IF ... THEN ... ELSE、WHILE ... DO、FOR ...）來描述演算法。虛擬碼無法直接被電腦執行，但能讓不同程式語言的開發者快速看懂演算法核心，並迅速轉換為 Python、JavaScript 或 C++ 程式碼。它是抽象思考邁向程式實作的關鍵橋梁！

4. 符號標準島

掌握 CNS 標準流程圖四大幾何符號，學會標準流程線與條件分支標示規範。

核心學習目標：熟練運用端點、輸入輸出、處理程序、決策判斷四大符號，並繪出合乎規範的流程線與條件標籤。

流程圖四大標準符號字典（CNS 標準）

為了讓所有人都能正確無誤地理解流程圖，中華民國國家標準（CNS）與國際標準組織（ISO）制定了統一且具備特定意義的標準符號： 1. 端點符號（橢圓形 / 圓角矩形）：代表流程的「開始」或「結束」。通常流程圖只會有一個「開始」端點，可有一個或多個「結束」端點。 2. 輸入／輸出符號（平行四邊形）：代表資料由外部讀入（例如輸入帳號密碼、讀取感應卡餘額），或運算結果向外顯示（例如螢幕顯示歡迎詞、印出總分）。 3. 處理程序符號（長方形）：代表系統內部的運算處理、變數計算或一般動作（例如計算「總和 = A + B」、更新資料庫、扣款 20 元）。 4. 決策判斷符號（菱形）：代表條件判斷，必定會有一個輸入端點，並分出至少兩條流向分支（條件成立與不成立，或 Yes 與 No）。

流程線規範與動態追蹤：決策流程圖怎麼跑？

繪製流程圖必須遵循嚴格的黃金規則： 1. 流程線一律必須帶有箭頭：明確指示資料與控制的唯一流向，不可使用無箭頭的普通直線。 2. 菱形決策線必須標註分支結果：由菱形分出的每一條流向線，一定要清楚標註『成立／不成立』、『Yes／No』或『是／否』！ 動態追蹤案例（週末活動決策）： 起點：橢圓『開始』 → 決策：菱形『是否下雨？』 分支 A (成立 / Yes)：走左路 → 長方形『去圖書館看書』 分支 B (不成立 / No)：走右路 → 長方形『去戶外打籃球』 匯合：兩條路徑最終匯流至橢圓『結束』。

[ ] 資料輸入（如輸入帳密）是否使用平行四邊形？
[ ] 運算處理（如加減計算）是否使用長方形？
[ ] 條件判斷是否使用菱形？
[ ] 菱形分出的兩條分支線是否有標註「成立 / 不成立」或「Yes / No」？
[ ] 所有流程連接線是否皆清楚標示前進方向箭頭？

5. 控制結構島

探索程式設計的三大基石：循序、選擇與重複結構，理解電腦邏輯的控制流程。

核心學習目標：能分辨循序、選擇與重複三大結構，並說明計數迴圈與條件迴圈的差異。

循序結構（Sequential Structure）

循序結構是所有程式中最基礎的架構。指令是由上而下、一條接著一條按照順序單向執行，中間沒有任何跳躍、分支或折返。例如：早晨起床鬧鐘響起 → 刷牙洗臉 → 換制服 → 吃早餐。每一步都按照既定順序發生。

選擇結構（Selection Structure）

當流程遇到需要判斷條件時，會根據條件成立與否，決定走向哪一條路徑，這就是選擇結構（又稱條件判斷分支）。常見形式有： 1. 單向選擇：若條件成立就執行某動作，不成立就什麼都不做直接跳過（例如：若下雨就帶傘）。 2. 雙向選擇：條件成立走路徑 A，不成立走路徑 B（例如：考試成績 >= 60 及格，否則不及格）。

重複結構（Repetition Structure / 迴圈）

如果希望某些指令重複執行多次，重複結構能大幅簡化程式碼，避免複製貼上上百行指令。常見類型有： 1. 指定次數重複（計數迴圈，如 FOR 迴圈）：預先知道要執行幾次，例如「原地開合跳重複 20 次」。 2. 條件成立時重複（條件迴圈，如 WHILE 迴圈）：依據條件動態決定是否繼續，例如「當水溫未達到 100°C 前，持續加熱」。特別注意：重複結構必須具有讓條件改變並終止迴圈的機制，否則會陷入停不下來的無窮迴圈！

三大結構特徵對照表

[循序結構]
指令 A -> 指令 B -> 指令 C (由上而下無分支)

[選擇結構]
條件成立？ -> 是 -> 執行區塊 A
          -> 否 -> 執行區塊 B

[重複結構]
重複條件滿足？ -> 是 -> 執行指令區塊 -> 折返檢查條件
              -> 否 -> 跳出迴圈結束
